## 1. 审核结论与本次交付

**原方案不通过直接实施审核。** “细密纹理的紧密团块为主要外观依据、取消暗核一票否决”的方向通过，但原方案不足以保证轮廓正确、安全定位及速度不退化。按用户“方案不通过则对方案进行改动”的分支，本次交付完整修订方案，不改运行代码；原附件作为待审材料，其中的实施步骤不视为额外用户指令。

本次完成源码与下游调用审查、历史计时文件核对、形态学及 CuPy 官方资料核查。未运行新的分割实验，也未完成目标硬件性能验收。当前执行环境 `nvidia-smi` 报告 RTX 500 Ada Generation Laptop GPU、4094 MiB，不能替代 3080 验收；当前默认 Python 缺少 cv2，这不代表部署环境也缺少依赖。

## 2. 识别目标的定义

目标是当前培养、倍率和成像条件下，具有连续细密细胞纹理、细胞排列紧密、边界相对清晰的 iPSC 候选克隆；同时排除平滑黑斑、孔壁、划痕、散在细胞和失焦噪声。亮度只用于曝光/饱和质量诊断，不以“足够暗”作为目标成立的必要条件。

ATCC 描述的典型 iPSC 外观包括紧密排列、清晰边缘及细胞高核质比，而非整个克隆存在暗中心。低倍图中是否能解析核质比取决于分辨率，不应据此直接构造低倍硬阈值。[ATCC 培养指南](https://www.atcc.org/resources/culture-guides/stem-cell-culture-guide)

培养基质会改变克隆的圆整度和边缘形态，因此圆度、长宽比和 solidity 只能提供形状证据，不宜把不圆整等同于非目标。[STEMCELL 基质形态对比](https://www.stemcell.com/vitronectin-xf.html)

这是形态候选检测与分割，不把图像规则分数解释为多能性鉴定结果。标注需明确：轮廓包围整个克隆还是仅致密可操作区。本版设计分别保留外轮廓与内部可定位区；有明显分化、无法确定边界的样本作为不确定样本，不强行给出可操作结论。

## 3. 原方案遗漏的实质问题

| 问题 | 已核实的代码或推导 | 修订要求 |
|---|---|---|
| 暗核仍决定进入主路径 | `segment.py:207` 的 `dark_core_area <= 0`，及其后多个暗面积门槛 | 纹理主路径不再受暗面积约束；保留暗字段仅供诊断 |
| local_std 不能独立区分纹理与边缘 | 平滑黑圆内部方差为零，但边缘窗口方差很高；形态闭运算可能把环填成实心团 | 增加内部纹理覆盖率、背景噪声下限和边缘集中程度验证 |
| 径向搜索会截短或跨团 | `segment.py:482` 所有方向共用距最近边界的半径；`:513` 取最后一次超过阈值 | 不规则轮廓采用连通纹理支持区域；径向仅作受约束可选细化 |
| bbox 名义裁剪实际为椭圆裁剪 | `segment.py:768` 调用 `cv2.ellipse(allowed, ...)` | 移除椭圆形状假设，改为图像/ROI矩形边界与实例支持域约束 |
| 高纹理点均值也可能落在背景 | 非凸或双峰纹理区域的均值不保证属于前景 | 从最终安全域选择实际像素并复核，不直接输出均值 |
| 现有安全点未依据最终轮廓 | `segment.py:816` 使用小图旧 mask；此后全分辨率裁剪、GrabCut及轮廓近似可能改变有效区域 | 安全点在最终输出轮廓栅格化后计算 |
| “纹理优先”与现有逻辑不符 | `_dedupe_mapped_coarse_results` 遇到跨来源包含框时保留/替换为 dark 结果 | 修复来源优先逻辑，并防止单纯 bbox 包含误删真实邻团 |
| 1024 不是实际严格上限 | `preprocess.py:21` 使用 round 得到整数倍；最长边 1400 时仍为 1400 | 使用显式输出尺寸和每轴真实比例；纹理尺度与倍率/缩放联动 |
| 1 px 往返保证混淆变换与采样 | 5倍缩小后坐标一旦量化到整数，恢复误差可能约2.5原图像素 | 把变换算术误差和分割采样误差分开验收 |
| JSON 新字段不会自然透传 | `_coarse_quality` 及两个 component builder 显式枚举字段 | 新字段在成功和失败路径均显式传递，验证序列化 |
| 下游优先读取 center_pixel | `workflow/detect_api.py:105`，随后检测与补偿 executor 计算像素偏移 | `center_pixel` 与 `safe_point` 保持相同原图坐标语义；只改 safe_point 无效 |
| 默认输出描述不准确 | `process_image` 无 out_dir 时仅返回结果 | 保持无目录不落盘；有目录默认写05/06/07，debug才增加01–04 |

此外，现有 GrabCut 只限制迭代下限，没有实现原方案建议的上限2。现有纹理 fallback 会丢弃所有触边候选，并限制长宽比和圆度，不能原样复制为主路径。

## 4. 修订后的处理流程

### 4.1 输入、尺度与背景

保留 `fromfile + imdecode + to_gray_u8`、中文路径兼容和原图坐标系。粗检初始最长边目标仍为1024，但需用样本验证缩小后是否保留细胞纹理；若小团纹理消失，采用较高分辨率或分块纹理统计再下采样，不能在粗检漏掉后寄望 ROI 补救。

局部标准差采用 float32：`sqrt(max(E[I²] - E[I]², 0))`，明确窗口大小、边界填充和归一化约定。根据倍率/有效像素尺寸选择细纹理与较大聚合窗口；必要时校正缓慢照明变化。CLAHE 不作为默认必选，以免放大空背景噪声。

禁止把任意近常量纹理图强制拉伸成完整0–255后直接 Otsu。设置通过负样本标定的噪声下限；无足够纹理证据时返回空候选。

### 4.2 纹理粗检与多候选

以纹理强度及邻域覆盖密度生成种子和较宽松支持区域；Otsu只用于存在有效纹理动态范围的图像。候选同时评估内部纹理覆盖、纹理相对背景对比、solidity、面积、长宽比及边缘集中程度。仅一圈高方差、内部平滑的黑斑不能因填洞自动成为有效团。

评分把纹理质量放在主体位置，solidity作为辅助。使用稳定的候选排序和相同分数时的坐标次序。取消基于暗面积的资格门槛；暗统计不得伪装成纹理统计，新增 `texture_coverage` 等独立字段。

保留多目标与 max_keep。只有证据表明是同一实例时才合并/去重；bbox 重叠不能独立证明两个真实团重复。相邻团通过独立种子、支持区域间的低纹理间隙进行区分；仅在粘连证据充分时对该 ROI 做有标记分水岭，限制过分割。

触边目标保留 `touch_image_border`、`image_border_sides`、`image_edge_clipped`。是否适合定位取决于可见支持区和安全余量；是否轮廓完整独立记录。避免一律删掉触边团，也避免把被截断的轮廓当成完整轮廓。

### 4.3 ROI 与轮廓

粗检携带种子/支持域关联，扩框约20%后在原图裁 ROI。把总扩框量显式计算，避免粗框扩边和细化扩边叠加不可控。1200与1600作为可比较配置；是否提高工作尺寸由边界质量及端到端耗时决定，不能仅凭10GB显存决定。

ROI 中重新估计纹理密度，使用高阈值种子与低阈值支持域的连通约束恢复目标形状，提取实际外轮廓。仅填小尺度孔洞、做有限平滑；较大低纹理空区保留到内部安全域中，不因外轮廓填充而变成可操作区域。

径向180向/hybrid可以保留为近星形目标的可选细化：按每条射线计算可见最大距离，从所属连通支持域寻找有持续性的向外下降边界，不搜索任意远处的最后亮峰。结果不得超出实例支持范围；非凸、粘连或证据不足时使用支持域轮廓或标记不确定，不能凭固定半径生成看似成功的轮廓。

移除强制椭圆裁剪。GrabCut仍默认 none，显式开启时只处理受限ROI，迭代最多2；对照基准不能借减少输出或关闭原先开启的处理制造加速。

### 4.4 安全定位与有效性

从最终近似轮廓重建 mask，再与真实纹理支持区相交得到候选内部区域；距离变换排除靠近边界、孔洞和分割间隙的像素。根据操作工具尺寸和定位不确定度定义侵蚀余量，不能凭空指定物理安全距离。

在剩余实际前景像素中综合纹理密度和边界距离选点，固定并列时规则。质心可以作选择参考，不能未经投影/校验直接成为操作点。输出前同时检查：在图内、在最终轮廓内、属于当前实例且达到所配置余量。没有安全区域时保留候选但显式 `is_valid_for_compensation=False`。

保持 `is_pickable = (is_valid_for_compensation is not False)` 的现有接口关系，但成功和失败结果都必须给出显式布尔值。有效性增加最终轮廓和安全域依据，不能继续仅靠粗检置信度及面积大于0判断。

`center_pixel == safe_point` 为原图 `[x,y]` 整数坐标，`contour_center_pixel` 单独保留几何中心。`dark_core_center_pixel` 如保留必须仍表示暗统计，不将其悄悄重命名为纹理中心。新增 `texture_center_pixel`、`safe_point_method` 与失败原因用于追踪。

## 5. 坐标与下游契约

逐级记录真实输入输出尺寸，用 `sx = W_original/W_small`、`sy = H_original/H_small`。点的像素中心、bbox的半开区间端点、mask缩放分别采用明确且一致的约定；最后一步才量化。不要把 ndarray 图像尺寸推导出的每轴比例硬塞入旧的单一 scale 接口而遗漏调用者。

保留入口签名兼容、components结构、bbox `[x,y,w,h]`、contour_points、面积和布尔字段。成功/失败路径新增 `detection_source`、`texture_score`、`texture_coverage`、`solidity`、`segmentation_status` 及诊断字段。旧调用参数要有明确兼容处理；纹理模式下未使用的暗参数记录为未启用，不静默改变单位。

贯通验证 `process_image → workflow.detect_api → detect_executor / compensate_executor`：同一输入的 safe_point 和归一化 center_px 一致，图像中心偏移、X/Y方向及毫米换算按既有约定执行。轮廓和定位点允许因算法纠错改变，“下游不受影响”指接口、坐标变换及有效性过滤正确，不要求继续输出旧的错误暗中心。

不恢复霍夫孔圆，不更改独立 instance_pipeline/ONNX入口或全局默认路由。规则GPU后端采用独立配置，不能直接复用当前 process_image 会丢弃的 model provider 元数据。

## 6. GPU 实施修订

先完成CPU纹理算法并冻结结果，再实现可选 `gpu_ops.py`。定义 cpu/cuda/auto：cpu始终可用；auto在不可用或设备故障时回退并记录后端/原因；显式cuda用于验收时应报告失败，避免误将CPU回退计时当作GPU结果。

局部均值、平方均值、标准差和密度平滑尽量留在GPU连续完成，减少主机/设备往返。Otsu是否放GPU由测量决定；不能把每一个小算子都强制搬到GPU。CPU和GPU使用相同窗口、边界、阈值定义，注意方差消减误差与Otsu并列阈值。

惰性导入CuPy、限制中间缓冲区与并发ROI；10GB仍需考虑CUDA上下文、内存池、其他视觉模型及并发任务。显存不足按ROI/批次降级，不每帧重复初始化失效后端。记录累计回退次数和峰值显存。

CuPy缓存目录可由配置或环境提供；尊重已有 `CUPY_CACHE_DIR`，验证可写。不能把 `C:\Temp` 写死成Linux部署路径，也不应预设所有中文路径都会失败。

计时区分初始化/编译、预热后算子耗时及完整流水线墙钟。GPU异步调用必须同步后结束计时；完整墙钟含读取、传输、分割、JSON/图像输出。CuPy官方明确说明了异步计时和首次初始化/编译开销。[CuPy性能指南](https://docs.cupy.dev/en/stable/user_guide/performance.html)

## 7. 验收设计

以下是实施验收设计，不是已经达到的成绩。图像质量阈值为首轮建议，最终应在固定标注集和设备误差预算下冻结。

**数据**：已找到附件提到的15张B3图片与历史计时JSON。历史文件为 `B3/run_timing_no_grabcut.json`，总计14.26秒、14个输出，其中B3_001为0、B3_004为5。这仅证明旧算法当时的输出数量，不证明B3_004真实应有几个目标。应逐张标注实例、边界及可定位区，并增加独立采集批次的亮团、暗团、多团、粘连、非凸、触边、黑斑、孔壁、散细胞、失焦及空背景样本；调参集和验收集分离。

| 验收项 | 要求 |
|---|---|
| 检测 | 固定实例匹配规则，如IoU≥0.5一对一匹配，报告precision/recall及各难例分组；首轮目标二者≥95%，关键样本逐一复核；不能仅用“有候选”验收 |
| 分割 | 报告匹配实例IoU/Dice、漏检、合并/拆分错误及边界距离；首轮建议中位IoU≥0.85、P10≥0.70；原图像素/微米边界误差需落入操作预算 |
| 安全点 | 全部is_pickable=True结果必须在输出轮廓及标注允许区内；满足配置的最小边界距离，禁止静默用粗中心兜底 |
| 坐标变换 | 浮点点位/框端点变换往返最终舍入误差≤1px；整数小图采样的误差另计，5倍缩小不能宣称总误差≤1原图px；覆盖非整倍尺寸、非方图、右下边界和ROI偏移 |
| 鲁棒性 | 亮度变化不因缺暗核漏检；空白/平滑阴影/黑圆/单线测试不误判为致密团；多实例、U形与相邻纹理峰测试不跨团选点 |
| CPU/GPU一致性 | 分开验算子误差与最终实例匹配；初始目标最终mask IoU≥0.995、中心差≤1原图px、可操作状态一致；临界阈值翻转须复核，不以数组近似相等替代语义验收 |
| 速度 | 同一3080主机、同输入、同输出选项，比较旧CPU、新CPU、新GPU，至少预热后各重复5轮；完整批次中位耗时及每张P95均不高于同机旧基线，并报告冷启动；14.26秒仅作历史参考 |
| 下游 | 入口、返回JSON、失败拒绝定位、归一化中心、轮廓透传、图像偏移和补偿变换通过契约测试；用mock/离线回放，不以真实设备动作代替单元测试 |
| 输出 | out_dir=None不写盘；指定目录默认05/06/07；save_debug=True再写01–04；同算法输出模式不改变结果 |

纯合成纹理能够验证工程边界，不足以证明iPSC识别准确。已有用实心暗圆构造正例的测试应区分“输出契约测试”和“生物外观正确性测试”，不能为维持旧暗圆正例而重新引入暗核门槛。

## 8. 实施顺序与文件范围

1. 固定代码快照、样本清单及现有规则基线；补充实例/边界/允许定位区域标注，确定倍率和定位误差预算。
2. `preprocess.py`、`segment.py` 实施CPU纹理主路径、连通支持域轮廓和最终安全点；先通过形态/几何测试。
3. `feature_extract.py`、`detect_pipeline.py` 完成参数和新增质量字段贯通，保留旧结构；验证下游接口。`image_loader.py`无必要不改；最终按面积排序策略保持，候选质量分与最终排序分开。
4. `gpu_ops.py` 实现相同算法的可选GPU算子及回退诊断；按目标部署平台锁定验证过的CuPy/CUDA依赖组合，不猜测与3080匹配的包版本。
5. 在3080执行质量、性能、内存和下游验收。保留CPU后端和旧快照以便回归定位。

复用 `tests/test_rule_vision_api_contract.py`、`tests/test_rule_vision_outputs.py` 的输出/入口测试，新增纹理、非凸安全域、多目标和缩放测试。`tools/benchmark_rule_vision.py` 可借用计时框架，但跨算法新旧结果允许变化，应以标注质量指标评估，不能以旧JSON逐字相等作为算法优化验收；同一候选算法不同输出模式仍要求结果一致。
